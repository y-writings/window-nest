# WindowNest

WindowNest は、起動中のアプリとそのウインドウをキーボードで選ぶ macOS ウインドウスイッチャーです。ウインドウが1つのアプリはアプリの確定時に直接前面化し、複数あるアプリは次の一覧でウインドウを選んで前面化します。矢印キーでアプリを選択しただけでは、前面アプリを変更しません。

## 動作環境

- macOS 14 Sonoma 以降（`SCScreenshotManager` を使用するため）
- Swift 6.0 以降 / Xcode 16 以降
- Accessibility（アクセシビリティ）権限
- Screen & System Audio Recording（画面収録）権限（サムネイル表示用）

初期検証対象は macOS 27.0.1 です。CI 環境は macOS 実機ではないため、実際のウインドウ列挙・キャプチャ・前面化については下記の実機確認手順を実施してください。

## ビルドと起動

macOS の Swift / Xcode ツールチェーンを使用します。

```bash
mise run app
open .build/WindowNest.app
```

| コマンド         | 内容                                        |
| ---------------- | ------------------------------------------- |
| `mise run build` | 開発用ビルド（`make build`）                |
| `mise run test`  | 自動テスト（`make test`）                   |
| `mise run app`   | Release ビルドと `.app` 作成・署名（macOS） |
| `mise run clean` | ホストのビルド生成物を削除（`make clean`）  |

mise がない場合は、従来どおり `make build` / `make test` / `make app` を利用できます。
タスク実行時のツール自動インストールは無効にしています。共通の lint ツールが必要な場合は、明示的に `mise install` を実行してください。

初回起動後、メニューバーの重なった四角形アイコンから WindowNest を表示できます。

## Docker での開発

Docker と Docker Compose を起動しておけば、ホストに Swift を追加せずに共通ロジックを開発・テストできます。
公式の Swift 6.0.3 イメージを digest で固定しています。Apple Silicon / Intel の両方に対応します。

```bash
mise run docker:build
mise run docker:test
mise run docker:shell
```

各タスクは必要なイメージをビルドし、終了時にコンテナを削除します。
ソースはホストのエディタで編集してください。`Package.swift`、`Sources/`、`Tests/` を読み取り専用でマウントするため、変更はコンテナ内にも反映されます。
ビルド生成物とキャッシュは Docker の名前付き volume に保存し、ホストの `.build/` や Swift キャッシュとは共有しません。
シェル内では `swift build` / `swift test` を実行できます。

mise を使わずに実行することもできます。

```bash
docker compose run --build --rm dev swift build
docker compose run --build --rm dev swift test
docker compose run --build --rm dev bash
```

ビルド生成物・キャッシュとプロジェクトのコンテナを削除するには、`mise run docker:clean` を実行します。
mise がない場合は `docker compose down --volumes` で削除できます。

Docker 内で検証できるのは Linux 対応部分です。macOS 固有の UI、ウインドウ操作、画面収録はコンパイル・実行されません。
`.app` の作成・署名と実機確認には、macOS 上のツールチェーンを使用してください。

## 権限設定

初回表示時の案内に従い、**システム設定 → プライバシーとセキュリティ**で次を許可します。

1. **アクセシビリティ**: ウインドウを列挙し、選択したウインドウを前面化するために必要です。
2. **画面収録とシステムオーディオ録音**: 静止画サムネイルの取得に必要です。
3. 設定後に WindowNest を終了し、もう一度起動します。

権限がない場合、一覧上に現在の不足権限と設定方法を表示します。サムネイルだけを取得できない場合も、タイトルと代替画像からウインドウを選択できます。

### 許可済みでも「Permissions Required」が表示される場合

既定の `make app` / `mise run app` はアドホック署名を使います。
コードの変更後に再ビルドすると署名の識別情報が変わり、システム設定のスイッチが ON でも、以前のビルドへの許可が現在のアプリに適用されない場合があります。
この状態は再起動だけでは解消しません。
[Apple による説明](https://developer.apple.com/forums/thread/819406)も参照してください。

設定画面での OFF / ON や削除・再追加でも直らない場合は、次の手順で古い権限登録をリセットします。

1. メニューバーの **Quit WindowNest** からアプリを終了します。
2. ターミナルで次の2つのコマンドを実行します。WindowNest のアクセシビリティと画面収録の許可だけをリセットします。

   ```bash
   tccutil reset Accessibility dev.ywritings.WindowNest
   tccutil reset ScreenCapture dev.ywritings.WindowNest
   ```

   **両方のコマンドで `Successfully reset` と表示されたことを確認してください。**

3. **システム設定 → プライバシーとセキュリティ**を開き、
   **アクセシビリティ** と **画面収録とシステムオーディオ録音** の両方で WindowNest を許可し直します。
   macOS のバージョンによっては、アクセシビリティは **Device Control and Data Access** と表示されます。
   一覧にない場合は **＋** ボタンから、現在ビルドした `.build/WindowNest.app` を追加します。
   ファイル選択画面で **⌘⇧G** を押すと、アプリの場所を入力できます。
4. 再ビルドせず、許可した `.build/WindowNest.app` を起動し直し、アプリ一覧が表示されることを確認します。

`No such bundle identifier` と表示された場合は、入力した ID が `dev.ywritings.WindowNest` と一致しているか確認してください。
末尾の `t` まで含めて入力する必要があります。

### 再ビルド後も権限を維持する署名

コード署名証明書がある場合は、同じ証明書を使ってビルドしてください。利用可能な証明書は次のコマンドで確認できます。

```bash
security find-identity -v -p codesigning
```

表示された証明書名または SHA-1 を `CODE_SIGN_IDENTITY` に指定します。

```bash
CODE_SIGN_IDENTITY="<証明書名または SHA-1>" mise run app
# mise を使わない場合
make app CODE_SIGN_IDENTITY="<証明書名または SHA-1>"
```

初めて署名方法を切り替えるときは、上記の手順で権限を登録し直してください。
証明書がない場合も既定のアドホック署名でビルドできますが、コード変更後に再登録が必要になることがあります。
ビルド時にもこの注意を表示します。

## 基本操作

既定のグローバルショートカットは **⌘⌥W** です。メニューバーの **Settings…** でキーと修飾キーを変更すると、設定は保存され即時反映されます。

| 操作                                        | キー            |
| ------------------------------------------- | --------------- |
| WindowNest を開く                           | ⌘⌥W（変更可能） |
| カードを選ぶ                                | ← / ↑ / ↓ / →   |
| アプリを確定する（1件なら直接前面化）       | Return          |
| ウインドウを前面化する                      | Return          |
| 表示番号のウインドウを直接確定する          | 1–9             |
| ウインドウ一覧から戻る / アプリ一覧を閉じる | Esc             |

ウインドウが選択中に閉じた場合は、前面化直前に同じプロセス ID と CGWindow ID が存在するか再確認します。存在しなければ別のウインドウを開かず、一覧を更新します。

## 初期版の対応範囲と既知の制約

- 現在のデスクトップで画面上にある、通常レイヤーのウインドウが対象です。WindowNest 自身、メニューバー常駐のみのプロセス、デスクトップ要素は除外します。
- 最小化ウインドウ、別 Space、フルスクリーン、複数モニター固有の配置は初期版の保証対象外です。
- サムネイルはウインドウ一覧を開いた時の静止画です。動画のような常時更新はしません。
- 公開 API の Accessibility API は CGWindow ID を直接公開しません。
  同一プロセス内で位置・サイズと取得可能なタイトルが一致し、CG と AX の両方向で候補が1つになる場合だけ前面化します。
  画面収録が未許可で CG のタイトルを取得できない場合は、位置・サイズから AX のタイトルを補います。
  同じ位置・サイズ・タイトルのウインドウなど、対応が曖昧な場合は前面化せず一覧を更新します。
- 標準のアプリケーション Exposé を変更するものではなく、独自パネルとして動作します。

## テストと実機確認

```bash
mise run test
```

Command Line Tools の環境で `TestingMacros` の読み込みエラーが出る場合は、`mise run docker:test` を利用してください。

自動テストは、アプリ単位のグループ、1件時の直接前面化、複数件時の2段階の状態遷移、矢印/数字選択、戻る操作、対象消失時の安全な選択更新、タイトルなし・取得不能時の位置照合、不一致・曖昧な候補の拒否を検証します。

macOS 実機では次を確認してください。

1. ウインドウが1つのアプリと、複数ウインドウを持つアプリを開く。
2. 別アプリを操作中にグローバルショートカットを押す。
3. ウインドウが1つのアプリは、Return で一覧を挟まず直接前面化され、パネルが閉じることを確認する。
4. 複数ウインドウを持つアプリは Return 後にそのウインドウだけが表示され、矢印＋Return、および 1–9 の表示番号で該当ウインドウが前面化されることを確認する。
5. Esc で1段戻り、もう一度 Esc で閉じることを確認する。
6. 選択中のウインドウを別の操作で閉じ、別ウインドウを誤って前面化せず一覧が更新されることを確認する。
7. ウインドウ確定前と Esc で閉じた後に、元のアプリが前面のままであることを確認する。
8. 画面収録が未許可でもタイトルと代替画像で選択でき、設定ボタンから画面収録の設定へ進めることを確認する。
9. Settings でショートカットを変更し、新しいキーで開けることと、Quit WindowNest で終了することを確認する。
